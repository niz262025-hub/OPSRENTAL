# Isolated document testing

`tests/fixtures/opsrental-test-schema.sql` is a synthetic fixture for a fresh, ephemeral local PostgreSQL instance. It uses only the `opsrental_test` schema and fixture-owned users, organizations, memberships, sessions, properties, tenancies and documents. It is not a migration, does not model Supabase Auth or Storage, is not a replacement for the production schema, and must not be applied to a shared or hosted environment. The PGlite test verifies that installation does not attach triggers to existing MYOPS or Auth tables and checks synthetic cross-organization references. Production foreign keys and authentication remain unchanged.

The API tests use simulated broker, database responses and Storage. They exercise expiry *parameters* and cache-control *headers*, but cannot prove signed URL expiry, browser or CDN caching, or actual storage access. Session and tenant denial tests do not prove full MYOPS SSO integration. The production handler accepts managers, admins and owners for document reads and rejects tenants altogether; there is no tenant document-sharing flow to validate.

For release evidence, use a dedicated, disposable Supabase project and private bucket with no shared production or SSO-staging data; confirm cost and quota before creation. Set up a separate test-only MYOPS-compatible broker with synthetic signing keys, user and organization records, grants, active and revoked sessions. Configure a branch-scoped Preview to use only those isolated endpoints and credentials. The current preview target allowlists in `api/rental/db-config.js` and `api/sso/myops-origin.js` are intentionally restricted to the existing shared staging endpoints: an independently reviewed, fail-closed test-only configuration is required to target a new dedicated environment. Do not point the current build at production or loosen the guard globally.

Before release, exercise actual upload, list, property and tenancy associations, view, download and delete; unauthorized and cross-organization access; tenant denial; revoked session and emergency disable; bad signatures and oversized uploads; bucket/backend failures; timeout and retry after ambiguous outcomes; object/metadata reconciliation; and desktop/mobile UAT. Request a signed URL, fetch before and after expiry, and check actual Storage, CDN and browser caching. Verify no anonymous access and that ordinary roles cannot bypass the server or access metadata. Preserve evidence and remove only explicitly identified synthetic data. No local or simulated Storage test can establish those results.
