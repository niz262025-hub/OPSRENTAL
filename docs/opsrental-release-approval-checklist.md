# OpsRental hosted UAT and production preparation

This is a review plan. No hosted change is authorized by its presence.

## Confirmed entitlement contract
MYOPS subscriptions use exactly one of `personal_user_id` and `organization_id`; company access additionally uses app grants. A personal subscription may authorize an organization owned by that user after the central broker verifies the product and the application verifies membership. The selected owner-only binding is conservative and needs product-owner acceptance. MYOPS trial admission is currently limited to OpsFlow, OpsFinance and OpsPS, and its quota implementation does not include OpsRental. A live 7-day trial for OpsRental therefore requires central admission and a verified quota enforcement contract; do not infer permission from an active trial row. MYOPS platform-admin access currently exists in the central broker but its entitlement response does not identify an administrator or authorize access to a specific organization. A trusted, organization-scoped admin contract is required before an admin bypass can be implemented safely. Existing session and organization checks remain mandatory.

## Preview approval checklist
- Identify a dedicated isolated, non-production Supabase database and private Storage project and a dedicated broker; do not use shared MYOPS SSO staging without separate approval. Confirm no added cost and no production data.
- Review the branch-scoped server-only variables `MYOPS_API_ORIGIN`, `MYOPS_RENTAL_SUPABASE_URL`, `MYOPS_RENTAL_SERVICE_ROLE_KEY`, `MYOPS_RENTAL_SESSION_SECRET`, `MYOPS_APP_PRIVATE_KEY`, and optional `MYOPS_RENTAL_ACCESS_DISABLED`. The current code hard-allowlists one shared staging broker and project; updating the allowlist to a dedicated target requires code review and tests. Do not copy production secrets into Preview.
- Authorized operators provision only synthetic users, memberships, organizations, properties and tenancies; register the OpsRental product and public app key with the isolated broker; verify server signing key correspondence. Confirm trial product eligibility and quota support before enabling any trial.
- Approve and apply only reviewed, test-environment-specific schema and Storage setup, confirm RLS and no anonymous access, and test database-to-broker isolation. Set branch-specific Preview variables and redeploy Preview only.
- UAT central SSO, Back to MYOPS, logout, revocation, owner/member/admin, personal and company subscriptions, trial quota, expiry, upload/list/view/download/delete, signed links and cache, desktop and mobile. Use synthetic records only.

## Production approval checklist
- Validate backup and restore readiness separately; enumerate legacy documents, owners, storage paths, dependent apps, existing RLS policies, grants, indexes and locks. Review `supabase/proposals/rental_production_review_draft.sql`; it deliberately refuses execution. It is not an approved migration.
- Agree how to verify and convert legacy rows from `pending` to `ready`, how to reconcile missing objects, and how to monitor `pending`/`deleting`. Never delete data to make validation pass. Validate owner/tenant RLS behavior and the exact indexes and constraints on a representative isolated copy first.
- Separately approve a private bucket and exact Storage policy changes. Determine whether the current production policies permit direct access to metadata or objects, and close bypasses without broadening other buckets. Apply via the supported Storage API; retain existing policies until reviewed.
- Prepare an additive, environment-bound migration, validate constraints, and verify counts, existing access and session behavior. If rollback is required, disable application access and restore the previously deployed application; retain the new columns and data. Do not roll back `lease_id` nullability or drop new fields while property-only records exist. A tested data-preserving recovery plan is required before production change.
- Review deployment, user-impact and rollback evidence; obtain explicit production migration approval, then separate PR merge and deployment approval. Never assume a ready Preview means a safe deployment.
